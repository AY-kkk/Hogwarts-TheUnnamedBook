# 《霍格沃茨：无名之书》公开 MVP 范围基线

- 文档状态：Frozen for P0 implementation
- 基线日期：2026-07-17
- 产品负责人：TBD
- 技术负责人：TBD
- 适用版本：Public MVP

## 1. 产品目标

公开 MVP 必须提供一个可持续、可恢复且规则一致的单人 AI 文字 RPG 闭环。用户能够创建角色，完成九回合入学序章，进入按周推进的正式学年模式，并在刷新、关闭或更换会话后继续当前角色的有效时间线。

本基线是 P0 实施和上线验收的唯一范围入口。后续变更必须按照“范围变更流程”处理，不以口头约定替代。

## 2. 目标用户与发布形态

- 目标用户：希望进行单人、长篇、沉浸式魔法校园文字跑团的中文用户。
- 发布形态：响应式 Web 应用。
- 核心语言：简体中文；咒语可以附带英文名。
- 数据策略：Local-First，角色和剧情以浏览器 IndexedDB 为主存储。
- AI 策略：后端托管模型凭据，客户端不得接触供应商密钥。
- 首发范围：邀请制灰度通过后再公开发布。

## 3. P0 必须包含的核心流程

### 3.1 进入与角色管理

1. 用户进入落地页并开始旅程。
2. 用户可以创建、选择和删除最多三个角色。
3. 每个角色拥有独立的角色状态、剧情日志、世界线和恢复点。
4. 新建或删除一个角色不得影响其他角色。
5. 已存在的旧版本地数据必须经过版本化迁移后继续可用，或向用户提供明确、可恢复的迁移失败提示。

### 3.2 角色创建

角色创建至少包含姓名、性别、血统、时代、初始特质、魔杖偏好、守护神和自我描述。提交前完成前端校验，服务端重复执行必要校验。

创建成功后，系统必须生成符合规则的初始状态，并开始序章 Turn 1。初始数据必须以统一状态 Schema 为准，不允许前端默认值、Prompt 规则和数据库字段各自定义。

### 3.3 九回合序章

序章一次回复只能推进一个 Turn：

1. Turn 1：猫头鹰与信。
2. Turn 2：家庭讨论与回信。
3. Turn 3：破釜酒吧与古灵阁。
4. Turn 4：购物与魔杖。
5. Turn 5：剩余假期。
6. Turn 6：车站送别。
7. Turn 7：特快列车。
8. Turn 8：分院仪式。
9. Turn 9：开学晚宴、宿舍与模式切换。

每回合必须依据当前状态和既有世界线生成，不得跳过必要信息或提前触发未来事件。涉及状态变化时，只能在回复末尾输出一个合法的增量状态包。

### 3.4 正式学年 Weekly Mode

- 默认一轮推进一周，每月只有四周。
- 每周提供 7 AP；透支和下周惩罚按核心规则执行。
- 回复遵循“叙事 → 结算 → 选择 → 状态更新”。
- 危机、情感爆发或大型活动触发 Event Mode，暂停周推进和常规 AP 消耗。
- 原著时间线只是默认参考；玩家造成的变化必须记录到角色自己的世界线并影响后续推演。

### 3.5 叙事与规则

- 行动输入先经过意图识别和世界观边界判断。
- 需要成败判断的行动必须由规则模拟器执行，不允许叙事模型自行决定骰点。
- 正常剧情回复以一级标题开始，正文目标为不少于 2000 个中文字符。
- 叙事必须使用第二人称、限制玩家视角，并遵守陌生角色匿名化要求。
- 非法或出戏输入给出世界观内可理解的拒绝，不改变游戏状态。
- Prompt、规则文件和状态 Schema 必须带版本号，便于回放和问题定位。

### 3.6 状态与持久化

P0 状态至少包括：

- 身份：角色 ID、姓名、性别、血统、时代、学院。
- 数值：HP、MP、最大 MP、金币、AP、最大 AP、学识、体能、魅力、品性、心智。
- 时间：年份、月份、周、星期、游戏模式。
- 场景：当前位置、章节和序章 Turn。
- 资产：物品、魔杖、宠物。
- 成长：咒语与熟练度。
- 社交：关系等级、标签和描述。
- 世界：角色独立的世界线变动记录。

状态更新必须经过 Schema 校验并在单个数据库事务内应用。解析失败时保留最后一个合法快照，正文可以显示，但不得写入部分状态。

## 4. P0 异常流

- LLM 超时、限流、供应商错误和网络中断。
- 用户主动取消生成。
- SSE 中断、重复事件和客户端重连。
- 非法或不完整的状态更新。
- IndexedDB 写入失败、配额不足和数据迁移失败。
- 页面刷新、浏览器关闭及恢复。
- 重复提交与同一角色的并发请求。
- 模型输出违法、危险或不适合未成年人的内容。

每类异常必须有明确的用户反馈、日志记录、可恢复策略和不重复扣费/写入的幂等边界。

## 5. P0 非功能门槛

- 生产环境全部使用 HTTPS。
- 模型密钥只存在于服务端密钥管理中。
- API 具备认证或匿名会话令牌、限流、输入长度限制和 CORS 白名单。
- 核心路径在干净环境中可重复构建并通过自动化测试。
- 生产发布支持审批、回滚、监控和告警。
- 隐私告知、AI 生成标识、内容安全和未成年人入口在公开发布前完成合规复核。
- 所有 P0 关闭后才能进入 Go/No-Go 评审。

## 6. 明确不在公开 MVP 范围

- 多人实时联机和 PvP。
- 实时语音或视频跑团。
- 云端多设备同步和社交账号体系。
- 付费订阅、道具商城和广告系统。
- AI 动态插画、语音合成和环境音效。
- 毕业后的完整生涯传奇模式。
- 原生 iOS、Android 或桌面客户端。
- MySQL 云存档和跨设备迁移。

上述能力不得阻塞 P0；如需加入，必须重新评估工时、合规、成本和上线日期。

## 7. 范围变更流程

1. 提交变更单，说明用户价值、优先级、工时、依赖、合规与成本影响。
2. 产品负责人、技术负责人和受影响领域负责人评审。
3. P0 范围增加必须同时给出删除项或新的发布日期。
4. 通过后更新本文件版本、验收矩阵和排期。
5. 未进入文档的变更不属于上线承诺。
